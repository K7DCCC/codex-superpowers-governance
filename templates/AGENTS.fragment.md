# Personal Codex Governance

## Capability routing

- When a task may need an extra Skill, read `{{CODEX_HOME}}/governance/level1-router.md` first.
- Read only the matching category and its Top-1 policy or capability card; do not scan the whole skill library.
- Given information is enough: prefer `baseline-direct` and do not load another Skill.

## Superpowers

- Apply `{{CODEX_HOME}}/governance/superpowers-governance.md` before any Superpowers workflow upgrade.
- Ambiguous wording is not permission to expand the workflow. Inspect the relevant project context first and default to the smallest reversible path.
- Skills marked `explicit-only` must not be implicitly invoked or automatically chained.
- Ask once before `brainstorming`; invoke it only after unresolved material ambiguity and user confirmation.
- `verification-before-completion` may run conditionally, with verification proportional to the change.
- Installation, login, external publishing, deletion, configuration changes and skill-visibility changes require separate confirmation.
