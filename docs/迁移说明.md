# 迁移说明

## 推荐流程

1. 在源电脑对本仓库运行 `scripts/audit_bundle.py`。
2. 把仓库推送到私有远程 Git 仓库。
3. 在目标电脑克隆仓库。
4. 关闭 Codex。
5. 运行预检和 dry-run。
6. 安装后重启 Codex并新建任务。
7. 运行结构验证和 README 中的新会话行为验收。

## 安装器会修改什么

- `$CODEX_HOME/AGENTS.md`：合并一个有明确起止标记的治理区块。
- `$CODEX_HOME/config.toml`：移除旧的 Superpowers 插件表、旧的插件缓存技能路径条目，再写入新的受管区块。
- `$CODEX_HOME/governance/`：安装三份治理事实源及安装状态。
- 用户技能目录：安装 14 个受治理的 Superpowers 技能副本。

安装前的相关文件和同名技能会备份到：

```text
$CODEX_HOME/governance/backups/portable-superpowers-governance-<UTC时间>/
```

## 安装器不会修改什么

- 其他插件的启用状态
- 模型和 reasoning 配置
- MCP server 配置
- 项目信任列表
- 登录态、API Key、会话和状态数据库
- Superpowers 插件缓存中的原始文件

## 版本升级

当目标电脑缓存的 Superpowers 版本不是 6.2.0 时：

1. 不要直接从新版本缓存覆盖本仓库。
2. 比较 14 个技能的文件变化和新增/删除的技能。
3. 重新确认各技能的隐式调用策略。
4. 更新 `manifest.json` 和第三方许可证。
5. 在隔离的 Codex 环境中重新运行结构验证和四项新会话行为验收。

## 多次安装

安装脚本可重复运行。每次安装都会创建新的时间戳备份，`rollback.py` 只回滚最近一次安装。需要回到更早状态时，人工选择对应备份，不要直接删除现有文件。
